## Decision 001: Evidence-based verification status

- **Rule:** A frontend verification stage can only be marked **PASS** or **FAIL** if it actually ran. A stage that was blocked before it ran must be reported as **NOT RUN**.
- **Why:** Earlier verification attempts were blocked by runtime permission prompts before the command could run. Calling those stages passed or failed would be a conclusion with no evidence behind it. Using three states keeps problems with the app separate from problems with the environment.
- **Rejected alternatives:**
  - A single pass/fail result for the whole run, because it hides which stages actually ran.
  - Reusing results from a previous session, because each report must use current evidence.
- **Scope and review trigger:** It covers the MediaVault frontend verification workflow. It should be reviewed if the workflow, the permission model or the reporting requirements change significantly.
