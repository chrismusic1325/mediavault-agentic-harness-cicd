## Correct routing

1. **Planner (`pagination-planner`, read-only: Read, Grep, Glob)**
   - **Input:** the bounded task (controller pagination for `/api/items`), relevant paths (`MediaItemController.java`, `MediaItemDao.java`, `MediaItemControllerTest`), decisions 002–004, the deferred work list, and the DAO gap above.
   - **Output:** exactly these sections: Scope, Ordered plan, Expected files, Acceptance criteria, Open questions.
   - **Gate:** the orchestrator checks that all five sections are there. If any is missing, the plan goes back to the Planner.

2. **Human approval checkpoint.** Nothing is implemented until you approve the plan, including how the DAO gap is handled.

3. **Implementer (file read/write; no test runner or task tracker)**
   - **Input:** only the approved plan, the paths, the constraints and the acceptance criteria.
   - **Constraints:** optional `page`/`size` that must be supplied together, zero-based pages, HTTP 400 for invalid input, a maximum size of 100, the plain-array response kept as is, and no deferred work (no envelope, total count, frontend controls or collection endpoints).
   - It can't grade its own work.

4. **Reviewer (`pagination-reviewer`, strictly read-only)**
   - **Input:** the changed files and the acceptance criteria.
   - **Output:** Verdict, Evidence, Blocking issues, Non-blocking observations, Recommended next route.
   - **REVISE** → back to the Implementer with the blocking issues.
   - **PASS** → on to the Tester.
   - The Reviewer must never fix code itself. That would destroy the independence of the review.

5. **Tester (file read and test runner; no writes)**
   - It runs the controller tests and reports PASS or FAIL with command evidence. Any stage that didn't run is reported as NOT RUN (decision-001).
   - **FAIL** → back to the Implementer, then through the Reviewer again before testing again.
   - **PASS** → hand the result to you before any final or shared action, such as a commit.

6. **Escalation:** if the same gate fails twice (two REVISE verdicts or two test failures), the loop stops and goes to you.

## What a correct run looks like

- The Planner runs first, and nothing is implemented without your approval.
- Each handoff carries only the bounded context it needs.
- The Reviewer never writes files.
- Test results come from real commands.
- Deferred items stay out of scope.
- Failures loop back at most once per gate before going to you.
