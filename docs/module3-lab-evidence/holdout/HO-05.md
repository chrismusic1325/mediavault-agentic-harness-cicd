**HO-05 answer:** When memory and the current Git working tree disagree about what is implemented, the working tree wins. Memory still counts for intent, decisions and deferred scope. The disagreement should be reported, not quietly resolved either way. I didn't modify any files.

## The rule, and where it comes from

| Source | What it says |
|---|---|
| `CLAUDE.md`, "Repository Authority" | Memory supplies context and decisions. Current source code, tests, configuration and Git state are the source of truth for what is implemented. |
| `.memory/knowledge/coding-standards.md:42-46` (read-only, human-maintained) | "Repository Is the Source of Truth for Code State": same rule. |
| `CLAUDE.md`, "Stale Memory Policy" | An entry past its `Review by` date is untrusted until a human confirms it. Repository evidence may only be used to explain the conflict, and expired memory must not be chosen over it silently. |
| `.memory/reference/lessons/repository-authority.md` | This exact case happened before. The fix is to compare status claims against the repo and report any disagreement. |

So there are two separate checks. An expired review date makes an entry untrusted. But an entry that is in date can still be wrong about code state. Being in date makes memory trustworthy for decisions, not for what is implemented.
